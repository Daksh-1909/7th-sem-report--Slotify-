\chapter{Implementation}

\section{Backend Implementation}
The backend of Slotify is built using Node.js and Express.js. It manages authentication, appointment processing, service queries, and business logic. A structured routing and controller pattern is used to keep the application organized and easier to maintain as the project grows.

\subsection{Project Structure}
The backend project is organized into modular folders such as controllers, models, middleware, routes, and utilities. This separation allows the system to manage business logic, validation, and database access more efficiently. A clear project structure is essential in a platform that supports multiple user roles and different services.

\subsection{Slot Availability Logic}
The slot availability engine checks for business working hours, staff schedules, and existing bookings before rendering available times. It uses rules such as service duration, business policies, and staff availability to determine valid appointment windows. This logic prevents conflicts and maintains the reliability of the booking system.

\subsection{Authentication Middleware}
Authentication middleware verifies user identity before allowing protected API access. It ensures that users are logged in and that only authorized users can view or modify relevant business data. This is important for preventing unauthorized actions and enforcing role-based access.

\subsection{Email Notification Service}
The system includes an email notification service to send confirmation messages and reminders to customers. These notifications help reduce missed appointments and improve communication between the business and the customer. The service is integrated into the booking and reminder flow to keep the scheduling process reliable.

\section{Frontend Implementation}
The frontend is built using React, which provides a responsive and interactive interface for customers, admins, and staff. It is designed to present a clear booking flow, show available time slots, and manage user actions across different roles.

\subsection{Project Structure}
The frontend is organized into reusable components, pages, routes, and context-based state management. This structure improves maintainability and allows the UI to scale as the platform evolves. It also keeps the login, dashboard, and business booking flows separated into well-defined modules.

\subsection{Real-Time Slot Display}
The booking interface updates available time slots dynamically based on current data and business rules. Customers can see only valid appointment times, which improves the user experience and prevents the confusion associated with manual scheduling. The real-time slot display is a core part of the platform's operational value.

\subsection{State Management and Prop Drilling Refactor}
As the application grew, state management became more complex. The project addressed this by reducing unnecessary prop drilling and centralizing shared state where necessary. This made the application more maintainable and improved the consistency of booking, authentication, and dashboard data across components.

\section{Implementation Status}
The application has implemented the core features needed for a functional booking system, including user authentication, business discovery, service booking, reminders, and scheduling logic. The project is now in a working state and demonstrates the viability of the solution for small service-based businesses. Further enhancements such as payments, AI recommendation, and mobile support can be added as future extensions.
